# 历史资料与仓库一致性整理设计

## 目标

在不破坏五项独立 Skill 安装边界、不给历史记录断档的前提下，降低当前文档与历史状态混淆的风险，并让评测资产和仓库元数据可以持续校验。

## 现状判断

- 当前仓库有五项独立 Skill 和 39 个 eval case。
- `README.md`、`skills/` 与 `agent/` 是当前用户和维护规则的主要入口。
- `docs/archive/` 已保存研究、评测、设计、计划和发布草稿，但目录名称混合了内容类型与产生这些文件的工作流。
- 部分历史材料保留了旧状态，例如四项 Skill、38 个 prompt 或尚未加入 `management-retro` 时的边界。这些内容应保留为历史快照，但需要通过索引和状态说明防止被当作当前事实。

## 设计

### 当前入口与历史记录分层

保留以下当前入口不变：

- `README.md`：用户目录、安装和边界。
- `CHANGELOG.md`：版本与发布变化。
- `agent/`：跨 Skill 的当前规则和 ADR。
- `skills/<name>/`：可独立安装的 Skill、参考资料和 eval。
- `examples/`：用户可阅读的案例。

将归档目录按内容类型重排为：

```text
docs/archive/
├── README.md
├── index.md
├── research/
├── evaluations/
├── decisions/
├── plans/
└── publication/
```

历史文件正文原则上不重写。通过移动、索引和必要的状态注释保留其时间点、来源和后续影响；只有仍作为发布草稿使用的材料可以更新当前数字。

### 归档索引

`docs/archive/index.md` 为每个归档主题提供类型、时间、状态、用途和当前替代入口。历史文件不要求全部添加 frontmatter，避免对旧文档造成无必要的内容噪声。

### 一致性校验

新增 `scripts/check_consistency.py`，只依赖 Python 标准库，检查：

- 五项 Skill 的名称与入口数量；
- 每项 Skill 至少有正常、缺信息、冲突信息三类 eval；
- eval 总数与维护文档中声明的当前数字一致；
- README 的 Skill 链接和归档索引中的当前入口存在；
- 历史文档中的旧数字不被误判为当前数字，因为它们位于 `docs/archive/` 且由索引标明为快照。

校验失败时输出具体文件和原因，并以非零状态退出。现有 `validate_repo.py` 继续负责结构、JSON 和 Markdown 本地链接检查；两个脚本职责不合并。

## 不做的事

- 不新增根路由 Skill。
- 不删除或合并历史文档。
- 不把所有研究结论升级为当前规则。
- 不引入第三方测试框架或网络访问。
- 不把评测分数包装成跨模型或真实业务效果证明。
