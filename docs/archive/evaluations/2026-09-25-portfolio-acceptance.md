# 五项工程分析与决策 Skills 验收报告

- 验收日期：2026-09-25
- 验收范围：项目定位、社区对照融合、独立安装结构、现有行为评测证据与仓库完整性。

## 验收结论

**可以作为小范围试用对象，仓库也具备安装分发条件。**五项 Skill 都有独立入口和具体任务边界；每项 eval 至少覆盖缺数据、冲突信息和正常任务；已有单轮案例记录显示它们能生成有用的辅助分析/决策输出，并记录了被发现和修正的事实边界问题。

**尚不能声称普遍有效。**这些证据是仓库内小样本的 prompt 评测和人工量规评分，不是外部用户研究、盲测、多模型评测或真实业务结果。最稳妥的对外承诺是：技能帮助结构化判断和暴露证据缺口，不能保证更好的组织决策或生产结果。

## 用户定位与产品边界

根据作者澄清，目标是让工程师、Tech Lead、项目参与者及产品/数据协作者，在具体工作中使用五项辅助分析和决策技能。现有能力保留为：

| 技能 | 一线工作中的问题 | 产出 |
| --- | --- | --- |
| `tech-planning` | 有限工程能力投在哪里，做/缓/停什么？ | 选项、取舍、决策门和重评条件 |
| `metric-decision` | 数字测量什么，变化可信吗？ | 口径、有效性检查、有限解释和验证动作 |
| `tech-review` | 现有方案是否足以支持决定？ | 有依据的问题、影响、动作及有边界的结论 |
| `management-retro` | 已完成的工程工作能支持什么学习？ | 系统模式、因果边界和下一轮小行动 |
| `eng-reporting` | 怎样把已有结论交给需要判断的人？ | 保留来源与未知状态的读者适配摘要 |

这五项独立按任务调用，不是必须依次完成的流程。项目不扩展成招聘、1:1、绩效、人员画像、团队士气或全面管理建议工具；`eng-reporting` 传达已形成的事实/判断，不负责一般沟通教练；`management-retro` 分析工作系统，不诊断员工。

目录组织保留 `skills/<name>/SKILL.md` 的独立安装入口，跨技能方法保留在 `agent/`，证据/评测和研究留在 `docs/`，每项技能的案例与参考材料留在各自目录。这个结构已适合用户挑选和单独安装，不需为了和更广泛竞品一致而重排。

## 社区对比后的定位

`manager-dot-dev/manager-skills` 是直接的工程管理领域对照，覆盖人员、团队、生产力、路线图、业务框架和沟通，也以作者文章与经验为来源。它说明“从个人写作提炼”不独特；其更广的范围也不意味着其效果已获证明。

本项目不通过增加更多管理场景追赶覆盖面，而是把差异假设放在五类边界清楚的工程判断上：投资取舍、测量有效性、方案决策就绪度、已完成工作的系统学习、基于已知事实的决策沟通。值得借鉴的是具体触发、简明结论、少问关键问题和下一步可执行。Matt Pocock Skills / Han 仍是软件交付、计划和评审方法的相邻参照。

“五项工作流加证据状态控制”是产品定位和待验证价值假设，不是已证明的竞争壁垒。社区调研来源与逐项比较见[GitHub 调研报告](../research/2026-09-25-github-demand-utility-review.md)。

## 行为证据

下列结果摘自仓库现有的单轮人工评测记录，本轮整理定位文档时没有改动 Skill 行为指令，也没有把这些历史结果重述为本轮新跑出的结果。

| 技能 | 覆盖情况及记录结果 | 可支持的结论 |
| --- | --- | --- |
| `tech-planning` | 有缺数据、优先级冲突、正常路线图、未确认负责人及压力/公开案例；一轮三场景曾出现 9/10 的未确认 owner 过度归属，收紧后同类场景复跑 10/10 | 已捕获并修正某个责任边界失误；不能证明跨场景稳定优于基线 |
| `tech-review` | 缺证据、冲突数据、无阻塞正常评审、deadline 压力、隐私评审边界及公开迁移案例；记录中的代表性样例为 10/10 | 能按依据/影响/动作组织发现，允许无阻塞时通过；专项审查边界仍重要 |
| `eng-reporting` | 缺数据、冲突口径、正常更新、夸大贡献、字数限制和复盘路由；公开事故材料首轮为 7/10，修订后目标回归 10/10 | 已修复特定字数和缓解效果夸大问题；报告仍应只整理给定材料 |
| `metric-decision` | 缺失数据、口径冲突、正常指标设计、因果边界、覆盖率下降、护栏权衡和公开 MR Rate 案例；代表性样例一轮为 10/10 | 能在样例中区别测量有效性和因果解释；没有真实数据系统接入或真实决策效果证据 |
| `management-retro` | 8 个案例覆盖正常复盘、缺证据/追责压力、冲突叙述、反例、因果/分母、未知 owner、汇报路由和指标路由；3 个匹配对照的修订后结果为 10/10，两个初始 9/10 的事实克制问题均针对修复并重跑 | 能在这些提示中避免选边、伪造根因/责任；样本少且由项目内评估者单轮评分 |

另有四项旧技能对四个公开一手来源案例的首轮合计为 baseline 38/40、skill 36/40；发现规划回答冗长以及汇报超字数/夸大缓解效果。两项定向回归修订后为 10/10 和 10/10。最新按案例合并是 skill 40/40、baseline 38/40，但它不是同一批次重跑，不应宣传为技能普遍提高了分数。细节见[公开案例评测](public-case-evaluation.md)、[技能组合评审](skills-portfolio-review.md)、[`management-retro` 评测记录](management-retro-evaluation.md)。

## 下一步验证

最有价值的后续不是再增加一个技能，而是找少量愿意试用的一线用户，用脱敏的真实规划、指标、评审或复盘输入，比较他们平时的分析与 Skill 输出。记录它是否揭示了真实的证据/口径问题、改变了行动或置信度、节省或增加了多少复核工作，并保留失败和“没有增益”的例子。若主要效果只是统一格式，就按结构化检查表和写作辅助来介绍，不宣称决策质量提升。

项目不需要 npm 发布。当前 Markdown Skill 可以直接从 GitHub 单项安装；只有增加独立可执行 CLI 或共享运行时后才需要重新判断。当前版本适合小范围试用，是否产生真实价值仍需用户场景验证。
